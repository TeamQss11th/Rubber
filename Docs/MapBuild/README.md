# Villa Lighting Study — 첫 맵 작업

> 과거 기록: 2026-09-22 사용자 요청으로 VillaLightingStudy와 BeforeExpansion 씬은 삭제했다. 이후 작업 대상은 기존 Beach Villa 씬이다. 아래 조작·빌드·검증 기록은 삭제된 시험 씬에 관한 것이다.

## 열기와 조작

Unity에서 `Assets/_Project/Scenes/Test/VillaLightingStudy.unity`를 연다. Play 후 Game 화면을 클릭하면 마우스 시점이 잠긴다.

- WASD: 걷기 / 마우스: 시점 / Esc: 마우스 해제.
- F1: 낮 / F2: 해질녘 / F3: 밤 / F4: 자동 순환.
- 노란 오리 모양은 기본 도형으로 만든 **위치 표식**이다. 수집과 반환은 아직 구현하지 않았다.
- 수영장은 정적인 불투명 수면 시제품이며 수영 기능이 없다. 가장자리에 진입 방지 충돌체가 있다.

## 이번에 만든 것

- Modern Villa의 원래 크기를 유지한 10×6m 거실·다이닝, 전면 유리와 2m 출입구.
- 14×4m 테라스, 5×6m 수영장 프리팹, 양쪽 선베드와 둘레 보행로.
- 소파·식탁·의자·조명·화분·야자수, 6개 오리 위치와 반환 지점 표식.
- 주광원 하나를 사용하는 낮·해질녘·밤 조명 시험, 1인칭 검토용 이동.
- 제작·화면 캡처·동선 검사·개발 빌드를 위한 `Rubber > Map` 에디터 메뉴.

## 적용한 비용 제한과 최적화

| 방법 | 목적과 범위 |
|---|---|
| 주광원 1개, 실내 Spot 2개, 외부 Point 2개 | 광원을 무제한 배치하지 않음. 낮에는 추가 광원 꺼짐 |
| 외부 Point 그림자 꺼짐 | Point 그림자 렌더 비용 방지. 실내 Spot 2개만 추가 그림자 사용 |
| 자동 시간대 변경 10Hz | 조명·환경 값을 매 프레임 갱신하지 않음 |
| 바닥의 단순 박스 충돌체 | 충돌체가 없는 테라스에 타일별로 복잡한 충돌을 추가하지 않음 |
| 작은 장식의 충돌 비활성 | 컵·책·수건 등에 불필요한 물리 충돌을 만들지 않음 |
| 실시간 반사 프로브와 추가 물 반사 카메라 없음 | 반사 재렌더링 비용 억제. 수면 품질은 시제품 수준 |
| 공유 재질 및 정적인 환경 표식 | 렌더러마다 재질을 복제하지 않음. 정적 배칭 후보 지정 |
| SRP Batcher 유지 | 기존 활성 설정을 유지한 것이며 새 최적화 성과로 집계하지 않음 |

PC_RPAsset의 그림자 50m/4 cascades, SSAO 등 전역 설정은 기준값 비교를 위해 변경하지 않았다. Occlusion 관련 static 표식은 있지만 Occlusion bake는 아직 하지 않았으므로 가림 처리 최적화가 완료됐다고 볼 수 없다. 정적 배칭 효과도 별도 측정 전이다.

## 검증과 수정

- Unity에서 새 코드 컴파일 및 씬 생성 실행.
- `scene-audit.txt`: Renderer 226개, Light 5개, 그림자 지원 Light 3개, 누락/지원되지 않는 재질 슬롯 0개.
- `route-validation.txt`: 0.28m 반경으로 입구·거실·수영장 순환 경로 222개 지점의 바닥과 캡슐 여유 확인. 통과. 실제 수집 동작까지 검증하는 검사는 아니다.
- 전체 및 실내의 낮·해질녘·밤 6개 화면을 캡처했다. 초기 야간의 벽 시인성을 높였고, 주전자와 오리 표식 겹침·책 방향을 보정했다.
- 처음 캡처의 빈 화면은 첫 렌더 준비 문제로 보고, 캡처 전에 렌더를 한 번 더 수행해 수정했다. 게임 루프에는 추가 카메라를 남기지 않는다.
- 변경 전 기존 맵 성능 측정은 없다. 이번 측정은 새 시험 맵의 첫 기준값이며 개선율을 계산할 수 없다.

## 성능 측정 재현

`Rubber > Map > Build Study Player`는 이 씬만 `Builds/VillaStudy/RubberVilla.exe`로 Development 빌드한다. 기존 Build Settings 씬 목록은 변경하지 않는다.

실행 인수: `-screen-fullscreen 0 -screen-width 1920 -screen-height 1080 -villaBenchmark <결과 파일의 절대 경로>`.

명시한 인수로 실행할 때만 자동 카메라 검사가 시작된다. 12초 준비 후 60초 시나리오를 3회 반복하며 각 시나리오는 낮·해질녘·밤 20초씩이다. 각 모드에서 입구·실내·수영장 시점을 고정적으로 바꾼다. VSync와 FPS 제한을 해제하고 종료 시 자동으로 결과를 기록한다.

기록은 전체 프레임 간격의 평균/p95/p99이며 개별 GPU 패스 시간은 아니다. 시작·모드 전환 직후의 타이밍 샘플은 이전 프레임 상태를 일부 포함할 수 있다. 전환 구간의 연속 애니메이션, 장시간 플레이, 물 반사 효과, 최종 배포 빌드 측정은 별도 검증이 필요하다.

## 남은 작업

- 실제 러버덕 모델·수집·반환 연결, 은신처별 접근 및 발견 플레이테스트.
- 물 표현과 식물의 어두운 면, 유리 반사, 해질녘 색감 세부 조정.
- 기준 GPU/CPU 사양 확정 및 GPU 패스·메모리 측정, 배포 빌드 검증.
- 성능 검증을 통과한 뒤 방과 정원을 확장한다.

## 기존 파일 주의

첫 생성에서 전역 AssetDatabase 저장을 호출하면서 이미 에디터에 로드돼 있던 Skybox, Modern Villa Lighting Settings, DefaultVolumeProfile도 저장됐다. Skybox 회전 변화는 본 생성 코드가 지정한 값이 아니므로 사용자 편집 가능성을 고려해 되돌리지 않았다. 이후 도구는 새 VillaStudy 재질만 개별 저장하도록 수정했다. 관련 변경은 맵 최적화 성과에 포함하지 않는다.
