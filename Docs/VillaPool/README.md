# 수영장 물·러버덕 첫 구현

Modern Villa 씬 뒤쪽 큰 수영장(Pool2)과 앞쪽 작은 수영장(Pool Level/Pool)에 적용했다. 오리 5종의 테스트 배치는 뒤쪽 수영장에만 있다. 앞쪽 수영장은 같은 물 재질과 부력 영역을 적용했으며, 요청에 따라 별도의 플레이 테스트는 하지 않았다. 설치 수치는 `second-pool.txt`에 기록했다.

## 테스트 방법

1. Modern Villa 씬에서 Play.
2. F12: 뒤쪽 수영장으로 이동. 마우스로 아래쪽 수면을 바라본다.
3. B: 오리 5종을 다시 떨어뜨린다.
4. J: 첫 오리에 작은 외력을 가한다. 움직인 뒤 저항으로 멈추는지 확인한다.
5. 기존 N 키로 시간대를 바꾸거나 대괄호 키로 시간을 조정한다.

화면의 floating은 물에 잠긴 부력 지점이 있는 오리 수, settled는 낮은 이동/회전 속도와 바른 자세로 1초 이상 안정된 오리 수이다. 최종 게임 수집 수가 아니다.

## 구조와 범위

- `Modern Villa - Pool Water Test` 아래 수면, 영역, 테스트 오리 5개 배치.
- 원본은 `Assets/_Project/Prefabs/Ducks`의 FBX 모델 프리팹이다. 파일을 수정하지 않고 씬 인스턴스를 감싼 오브젝트에 Rigidbody, 몸통 BoxCollider, 부력 컴포넌트를 추가했다.
- 기본형, 풍선, 큰 머리, 유리, 장난감 칼 모델을 수평 최대 크기 32cm로 맞췄다. 첫 비교 테스트이므로 모두 질량 120g, 같은 몸통 충돌체를 사용한다. 액세서리 전체의 정밀 충돌이나 종류별 무게 차이는 구현하지 않았다.
- 수면 높이는 월드 Y=0.1m. 물 표면에는 단단한 콜라이더가 없다. 실제 벽/바닥 충돌체와 함께 동작한다.
- 기존 풀 내부 충돌면을 10cm 격자로 조사하여 수면 메시와 같은 부력 영역을 만들었다. 사각형 감지 영역 안에서도 실제 물 영역 마스크로 다시 검사한다. 바닥·벽 배치를 변경하면 이 마스크도 갱신해야 한다. 영역은 현재 씬의 월드 좌표에 고정되어 있다.
- 몸통 아래 4지점에 잠긴 깊이만큼 위쪽 힘을 적용하고, 지점별 속도에 반대되는 물 저항을 적용한다. 자체 추진력과 물살은 없다.
- 부력 컴포넌트는 등록된 물 영역에서 현재 오리가 위치한 수영장을 자동 선택한다. 두 수영장을 오갈 때 물 참조를 수동으로 바꿀 필요가 없다. 두 수영장은 수면 높이와 영역을 각각 보유하고 같은 물 재질을 공유한다.
- 화면의 작은 물결은 수면 법선 변화다. 물리 수면은 평평하게 유지하여 작은 시각 효과가 오리를 계속 흔들지 않게 했다.
- 물에 뜬 상태 이벤트 `VillaDuckBuoyancy.onSettled`를 준비했다. 점수/반환 처리, 플레이어 잡기·놓기, 중복 집계 방지 등 실제 게임 로직은 아직 연결하지 않았다. 잡는 동안 Rigidbody를 kinematic으로 만들면 부력이 중지되고, 놓으면 다시 적용된다.
- 수영·잠수, 물속 화면 효과, 입수 물보라, 물결 전파, 소리는 이번 구현 범위 밖이다. 테스트 플레이어는 물에 들어가면 기존 수영장 바닥을 걷는다.

## 비용을 줄인 설계

수면 품질 보완: 두 크기의 물결을 네 방향으로 혼합하고, 먼 거리의 미세 물결을 완화했다. 수면 아래 실제 수직 깊이로 색과 투과율을 계산하여 얕은 계단은 맑고 깊은 곳은 짙게 보이도록 했다. 굴절은 축당 최대 3픽셀로 제한하고 얕은 가장자리에서 줄인다. 굴절 위치가 수면 위 오브젝트를 가리키면 원래 화면 위치를 사용한다. 기존 환경 반사 설정은 유지했으며 반사 기능을 추가하지 않았다.

공유 재질 `PoolWater.mat`의 Ripple strength/speed, Water absorption, Depth color distance, Maximum refraction에서 조절할 수 있다. 두 수영장에 같은 설정이 적용된다. 부력 및 물리 수면은 변경하지 않았다.

- 물을 매 프레임 유체로 시뮬레이션하지 않는다. 수면 메시 1개, 투명 패스 1개, 간단한 법선 변화 사용.
- 추가 반사 카메라 및 매 프레임 반사 베이크 없음. 기존 환경 반사를 활용하고 낮/밤 반사 강도를 따른다.
- 부력은 오리당 4개 지점과 미리 저장한 영역 마스크 조회를 사용한다. 매 프레임 풀 메시를 레이캐스트하지 않는다.
- 프로젝트 품질 설정이나 기존 라이트맵/APV를 변경하지 않았다. 이번에는 60FPS 성능 보장 측정은 하지 않았다.
- 수면 품질 보완은 기존 카메라의 색·깊이 텍스처를 재사용한다. 물 픽셀당 깊이 조회가 기존 1회에서 2회로 늘고 깊이/물결 계산이 추가되므로 비용 증가가 전혀 없는 변경은 아니다. 추가 반사 렌더링은 없으며 실제 GPU 시간은 측정하지 않았다.

## 검증

Unity Play 모드에서 5종의 낙하·안정화, 외력 후 이동, 벽에 밀기, 물 밖 낙하, 재설정을 검사했다. 상세 수치와 실행 오류 수는 `checks.txt`, 모델 및 수면 조사 결과는 `setup.txt`에 기록한다. `day.png`와 `night.png`는 같은 시점에서 촬영한 결과다.

위 플레이 검사와 이미지는 최초 수면 구현 당시의 기록이다. 이후 수면 품질 보완은 별도의 플레이 테스트 없이 셰이더 컴파일만 확인했으며 `surface-settings.txt`에 기록한다. 최신 외형의 플레이 화면이나 성능 측정 결과로 해석하면 안 된다.

Editor 메뉴 `Rubber > Pool > Install First Water Test`는 초기 설치용이며 기존 루트가 있으면 중복 설치하지 않는다. 원래 씬 백업은 로컬 `BeforeWater.unity.backup`에 보관했다.
