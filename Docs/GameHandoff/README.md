# Modern Villa 게임 연결 안내

> 후속 작업: Player 브랜치 연결이 완료된 현재 상태는 `Docs/PlayerIntegration/README.md`를 참고하세요. 아래 내용은 연결 전 환경 씬 인계 기록입니다.

대상 씬: `Assets/_Project/Scenes/Modern Villa.unity`

## 이번 정리

- 테스트 이동 컨트롤러, 손전등, 문/수영장 테스트 입력, 기존 낮밤 미리보기 컴포넌트를 씬에서 제거했습니다.
- 테스트 및 샘플 카메라와 AudioListener를 제거했습니다. 게임 담당자의 플레이어 프리팹이 카메라와 AudioListener를 제공해야 합니다.
- 시간 시스템의 T/N/[ / ] 키 입력과 화면 디버그 표시를 제거했습니다. 자동 시간 진행은 유지합니다.
- 테스트 이동/조작/벤치마크 스크립트 8종을 `Editor/LegacyReview`로 이동했습니다. 과거 검증 도구의 소스는 보관하지만 플레이어 빌드에는 포함되지 않습니다.
- 검증 당시 테스트 오리는 씬에 없었습니다. 원본 Ducks 모델과 부력 스크립트는 유지합니다.
- 두 수영장, 문 8개, 라이트맵, APV, 낮밤 전환, 바닥/계단 보정은 유지합니다.

## 팀원이 연결할 지점

1. `Player Spawn - Villa`의 위치/회전에 실제 플레이어를 배치합니다. 씬에 게임 플레이어는 포함되어 있지 않습니다.
2. 문에는 `VillaSlidingDoor`가 붙어 있습니다. 상호작용 담당 코드에서 `Open()`, `Close()`, `Toggle()`을 호출합니다. 회전형/슬라이딩형 문 설정과 열림/닫힘 UnityEvent는 유지됩니다.
3. 실제 오리에 Rigidbody와 Collider를 설정하고 `VillaDuckBuoyancy`를 연결합니다. `floatPoints`는 오리 바닥 네 지점의 로컬 좌표로 설정해야 합니다. 기존 32cm 테스트 모델 기준 예시는 x=±0.09, y=0.035, z=±0.085입니다. 모델 크기에 맞게 조정하세요. `water`는 위치에 따라 자동 검색합니다.
4. 집어 들 때 Rigidbody를 kinematic으로 전환하고 놓을 때 해제합니다. 재사용/재배치 시 `ResetState()`를 호출합니다. `onSettled`는 물에서 안정적으로 뜨기 시작한 이벤트이며, 최종 반환 판정·중복 수집 방지·점수는 게임 시스템이 담당합니다.
5. `Modern Villa - Environment Lighting`의 `VillaTimeOfDay`가 자동 시간을 진행합니다. `SetHour(float)`로 시간을 지정하고 `running`으로 진행을 제어합니다. UI/입력은 게임 시스템에서 연결합니다.
6. 게임 시작/씬 로딩 및 Build Settings의 씬 목록은 팀의 전체 흐름에 맞게 연결해야 합니다. 이번 정리는 다른 브랜치를 병합하거나 기존 시작 씬을 대체하지 않습니다.

## 확인과 성능 범위

Unity 재컴파일 및 씬 검사 후 콘솔 0건. 씬에 남은 주요 기능은 문 8개, 시간 제어 1개, 수영장 물 2개입니다. 테스트 카메라, 이동 컨트롤러, 테스트 오리, AudioListener는 없습니다. 실제 플레이어 연결 후 이동/상호작용/수영장 반환 통합 테스트와 최종 빌드 검증이 필요합니다.

테스트용 입력 처리·디버그 GUI·카메라·컨트롤러의 실행 부담을 제거했습니다. 기존 물 셰이더 및 조명 갱신 주기는 유지하며, FPS 개선 수치를 측정한 것은 아닙니다.
