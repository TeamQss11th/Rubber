# Beach Villa 확장 작업 — 2026-09-27

기존 `Assets/Modern Villa/Scenes/Beach Villa.unity`를 확장했다. 새 씬이나 새 가시 모델은 만들지 않았으며, 기존 Modern Villa 프리팹·모델 379개를 크기, 콜라이더, LOD, 누락 재질 기준으로 목록화한 뒤 사용했다. 원본 빌라와 수영장은 중심 공간으로 유지했다.

## 설계 근거와 공간

건축가가 제공한 실제 빌라 설명에서 실내외 연결과 부지 경계 처리 원칙을 참고했다. 해당 건축물을 그대로 복제한 설계는 아니다.

- [Jesolo Lido Beach Villa / JM Architecture](https://www.archdaily.com/941304/jesolo-lido-beach-villa-jm-architecture): 수영장을 중심으로 한 공간 구성, 그늘이 있는 외부 휴식 공간, 식재로 구분하는 진입부와 경계.
- [Oceanique Villas / MM++ architects](https://www.archdaily.com/515917/oceanique-villas-mm-architects): 거실·식사 공간과 테라스의 연결, 안뜰과 정원, 외부와 주거 공간 사이의 완충 영역.

플레이 부지는 약 80 × 73m이며 배경 지형은 360 × 360m다. 이는 전체가 실내이거나 전부 같은 밀도로 꾸며진 면적이라는 뜻은 아니다. 서쪽 식사 정원과 스파, 동쪽 게스트 휴게동, 북쪽 진입 정원, 남쪽 라운지를 3m 폭의 순환로와 수영장 복귀 연결로로 묶었다. 부지 밖까지 이어지는 지형, 잔디, 여러 높이의 식물, 야자수, 낮은 담장과 유리 난간을 사용했다.

에셋의 `mv_skybox.exr`는 야간 사진이었다. 낮에 밝게 사용했을 때 별과 인공 조명이 보여 최종 낮 하늘에서는 제외했다. 낮은 Unity 대기 스카이 셰이더의 색·대기 두께·태양 크기·노출을 조정하고 옅은 원경 안개를 연결했다. 밤은 매우 어두운 하늘과 검은 안개를 사용한다.

기존의 기울어져 묻힌 파라솔을 라운지로 옮겨 세웠다. 게스트동의 수영장 방향 벽 모듈 일부를 열어 진입 공간을 만들고, 가구를 대화·독서·식사·휴식 기능별로 배치했다.

## 러버덕과 이동

24개 숨김 후보의 위치와 접근 위치를 `BeachVillaHideLocations`에 기록했다. 책과 테이블, 의자, 소파 옆, 화단, 스파 라운저 주변을 사용한다. 현재 보유 에셋 목록에는 러버덕 프리팹이 없어 새 오리 모델을 만들어 넣지 않았다. 이 데이터는 실제 러버덕 배치 및 수집 시스템 연결을 위한 지점이며, 오리를 줍고 수영장에 제출하는 게임 로직을 이번 작업에서 새로 구현한 것은 아니다.

- 0.5m 간격의 바닥·캡슐 검사로 수영장 복귀 지점과 연결되는 영역을 조사했다. 24개 접근점 모두 숨김 위치에서 수평 2m 이내다.
- 지름 20cm 검사 구가 가구 콜라이더 안에 겹치지 않도록 후보를 보정했다. 실제 오리의 크기와 잡기 방식이 정해지면 그 크기로 다시 검사해야 한다.
- 작은 소품 553개는 전용 레이어를 사용해 플레이어 CharacterController만 무시한다. 소품의 콜라이더 자체는 유지한다.
- 카펫·커튼의 통행 방해 콜라이더 44개를 껐다. 야자수는 잎 전체 대신 줄기 중심 캡슐을 사용한다.
- 출입문 전체를 막던 문틀 BoxCollider를 실제 프레임 MeshCollider로 바꾸고 문짝을 열린 위치로 옮겼다. 고정 유리에는 실제 메시 충돌을 사용했다.
- 실제 `CharacterController.Move`로 외부 순환로 4개, 본관 앞뒤 문, 게스트동 입구, 수영장 복귀로 총 8개 대표 구간을 검사했다. 결과는 `movement.txt`에 있다. 전체 맵의 모든 이동 조합을 검증한 것은 아니다.

조작: 클릭으로 시점 고정, WASD 이동, Shift 빠른 이동, Esc 해제, N 낮/밤, F 손전등, R 체크포인트 복귀, H 도움말. F1–F6은 기존 빌라, F7 식사 정원, F8 스파, F9 게스트동, F10 진입 정원, F11 남쪽 라운지다.

## 조명과 최적화

낮 `Default`와 밤 `Night` APV 및 정적 라이트맵을 실제로 다시 베이크했다. 낮 약 40.4초, 밤 약 25.3초였으며 각 시나리오에 라이트맵 3장이 생성됐다. `lighting.txt`와 생성된 에셋을 기준으로 확인했다.

- 고정 전등 16개는 Baked로 변경해 실시간 추가광 계산을 줄였다. 낮의 태양과 테스트 손전등은 기존 실시간 역할을 유지한다.
- 기본 라이트맵 밀도 16 texels/m, 최대 1024, 직접 샘플 32 / 간접 256 / 환경 128. 넓은 지형의 라이트맵 비중을 낮췄다.
- 작은 장식과 식물 등 1,804개 렌더러는 APV를 사용하도록 정리했다. 잎과 작은 물건마다 라이트맵 공간을 소비하지 않는다.
- APV는 L1, 기존 Low 메모리 설정, 시나리오 블렌딩 끄기를 유지했다. 원래 실내 볼륨을 유지하고 외부 범위를 확대했으며 게스트동에 세부 볼륨을 추가했다.
- 기존 LOD와 공유 메시·재질, 정적 배칭, SRP Batcher를 유지한다. 지형은 instancing과 거리별 상세도 설정을 사용한다.
- 낮·밤 라이트맵 인덱스와 UV 배치는 동일함을 검사했다. 정적 배칭된 UV를 런타임에 다시 쓰지 않게 수정했다.
- Unity LightingData가 재로드 시 원래 생성 경로를 참조하므로, 낮 라이트맵을 그 경로에 복원하고 밤 라이트맵을 별도 에셋으로 연결했다. 낮 파일과 보존된 낮 베이크의 해시 일치, 밤 파일과의 차이를 확인했다.
- 손전등은 카메라에 붙는 실시간 Spot 1개, F로 켜고 끄기, 거리 15m, Hard 그림자, 512 해상도 등급이다. 정식 손전등 모델이나 배터리 시스템은 포함하지 않는다.

APV와 라이트맵은 서로 다른 수광 경로이며, 움직이는 러버덕은 APV와 실시간 손전등 조명을 받게 된다. [Unity APV 설명](https://docs.unity.com/en-us/engine/6000.5/manual/lighting-overview/lighting/probevolumes/concept)을 참고했다.

## 검증 자료

`all-assets.tsv`: 전체 에셋 목록. `scene-structure.tsv`, `colliders-before.tsv`, `terrain-before.tsv`: 수정 전 구조 조사. `routes.txt`: 숨김 후보와 접근 검사. `movement.txt`: 실제 캐릭터 이동 검사. `lighting-bindings.txt`: 낮·밤 라이트맵 연결과 배치 검사. `runtime-lighting.txt`: 실제 Play의 밤 APV·라이트맵 상태.

PNG는 일반 Game View의 `ScreenCapture.CaptureScreenshot`으로 저장한 실제 화면이다. 이전 크래시와 연관된 수동 `Camera.Render`는 사용하지 않았다. 현재 Unity Editor에 기존 Persistent allocation 경고가 남아 있으므로 이것까지 해결했다고 주장하지 않는다.

성능은 별도 실행본의 `performance.csv`를 기준으로 판단한다. 1920×1080, VSync 끄기, 제한 FPS 없음, 7개 위치에서 낮/밤/손전등을 각각 측정하며 위치마다 3초 예열 후 4초를 수집한다. 전체 게임 로직·다수 오리 물리·다른 PC 성능을 보장하는 테스트는 아니다.

## 재작업 시 주의

`Rubber > Expansion` 메뉴에 조사·통행 검사·캡처·베이크·검증 실행본 빌드를 제공한다. 확장 생성 메뉴는 이미 확장된 씬에서 중복 실행되지 않는다. 베이크를 다시 하기 전 기존 `BeachVillaExpanded/Day`, `Night` 출력은 별도 보존해야 한다. 현재 도구는 기존 출력 파일을 덮어쓰지 않도록 중단한다. 원래 씬 백업 경로는 `backup.txt`, 베이크 전 백업은 `lighting.txt`에 기록했다.
