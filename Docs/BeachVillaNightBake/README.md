# Beach Villa — Night APV와 테스트 손전등

2026-09-27, Unity 6000.4.0f1 / URP 17.4. 기존 Beach Villa 씬을 수정했다. 새 씬이나 외부 에셋은 추가하지 않았다.

## 사용

- Play: 어두운 밤으로 시작, 손전등은 기본 꺼짐.
- F: 테스트 손전등 켜기/끄기. 카메라 방향을 따라간다.
- N: 낮/밤 전환. F1–F6: 기존 체크포인트, WASD: 이동.
- 입력은 Game View에 초점을 둔 상태에서 사용한다.
- 손·손전등 모델, 배터리, 습득 기능은 없는 조명 테스트 구현이다.

## 밤 조명

기존 Default 낮 APV를 유지하고 Night 시나리오를 추가해 APV-only 베이크를 완료했다. 베이크 중 방향광을 끄고 국소등을 따뜻한 색으로 설정했다. 환경광은 거의 0이며 하늘 노출 0.001, 환경 반사 0이다. 밤 베이크 L0/L1 파일은 3,407,872바이트이며 별도 optional 파일도 생성됐다. L1을 사용하는 현재 설정에서 optional L2 파일 크기를 그대로 런타임 GPU 비용으로 계산하지 않는다.

밤에는 낮 라이트맵을 일시적으로 제외하고 렌더러의 프로브 수광을 활성화하여 건물·가구도 Night APV를 받는다. **별도의 밤 정적 라이트맵은 생성하지 않았다.** 기존 낮 라이트맵 16개와 낮 APV 데이터는 유지한다. 낮 전환 시 원래 라이트맵 연결과 프로브 수광 설정을 복원한다. 밤의 정적 표면은 라이트맵보다 공간 해상도가 낮은 APV를 사용하므로 얇은 벽, 작은 틈과 접촉부는 추가 검토 대상이다.

플레이 시작 때 APV 초기화가 MonoBehaviour보다 늦게 완료되는 것을 발견했다. 이제 활성 베이크 세트가 준비되면 의도한 시나리오로 맞춘다. 매 프레임 비교하는 것은 현재 시나리오 이름뿐이고, 실제 데이터 전환은 불일치할 때만 수행한다. 전체 렌더러 검색은 활성화 시 한 번이다.

## 성능 비용 제한

- 기존 실내 최소 0.75m / 외부 최소 2.25m 프로브 배치, L1, Low 풀 유지.
- 프로브 위치를 고정하여 낮·밤 공유. 시나리오 지원만 켜고 블렌딩은 끈 상태로 즉시 전환한다. 두 시나리오는 저장 공간을 추가로 사용하며 전환 순간 지연은 별도 측정이 필요하다.
- 기존 국소등 10개 유지. 손전등만 실시간 Spot 1개 추가: 범위 15m, 외곽 48도 / 내부 28도, 강도 8, Hard shadow, PC Medium tier 512 해상도. 꺼져 있으면 Light 컴포넌트도 비활성이다.
- URP에서 custom tier가 Light.shadowCustomResolution 대신 Light.shadowResolution 값을 읽어 초기 시험에 아틀라스 축소 경고가 발생했다. 현재는 프로젝트의 Medium tier를 사용하며 수정 후 비교 촬영에서 해당 경고가 재발하지 않았다.
- 손전등은 플레이에서만 생성하므로 APV 베이크에 들어가지 않는다. APV가 손전등의 움직이는 간접광을 계산하는 것은 아니다.
- 기존 국소등 그림자를 추가하지 않았고, 카메라나 실시간 반사 촬영을 추가하지 않았다.

## 검증

[베이크 상태](bake-status.txt), [비교 촬영 상태](review.txt).

- Night 데이터 생성과 시나리오 목록 확인. 낮 Default의 CellData/CellOptionalData는 베이크 전 로컬 백업과 SHA-256 동일.
- 베이크 후 낮 라이트맵 16개 유지. Unity가 LightingData.asset 메타데이터를 다시 저장했으나 낮 APV 바이트는 동일하다.
- 1920×1080 일반 Game View에서 입구와 실내를 각각 직접광만 / Night APV / Night APV+손전등으로 촬영. 최종 6개 캡처 모두 `scenario=Night`, APV 배율과 손전등 상태가 기대값임을 확인했다.
- 입구 APV 비교에서 천장·벽·의자에 추가된 따뜻한 간접광 확인. 손전등 비교에서 조명 범위, 식물 그림자, 실내 가구의 밝기 변화 확인.
- 낮 전환 시 낮 화면 복원, 플레이 종료 시 편집 화면 복원 확인.
- 마지막 수정 후 플레이·촬영·종료에서 예외와 D3D12 크래시 재발은 관찰되지 않았다. 이전부터 있던 에디터 Persistent allocation 경고는 이번 컴파일 과정에서도 관찰됐으며 원인은 미해결이다.

**1920×1080 화면 검증은 했지만 60FPS 빌드 벤치마크는 하지 않았다.** 전 구역 빛샘, 손전등이 다른 국소등과 겹치는 곳의 광원 선택, 물·발광 재질, 낮밤 전환 지연은 추가 검토 대상이다. 배치와 조명이 바뀌면 Night를 다시 베이크해야 한다. 첫 베이크 메뉴는 기존 Night 데이터의 실수 덮어쓰기를 막도록 재실행을 거부한다.
