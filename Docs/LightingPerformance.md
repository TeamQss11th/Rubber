## 목표와 검증 조건

사용자 확정 목표는 1920×1080, 60FPS(프레임당 16.67ms)다. 기준 PC의 CPU·GPU·RAM은 아직 지정되지 않았으므로 성능 결과에는 측정한 PC 사양을 함께 기록하고 다른 사양까지 보장하지 않는다.

완성 맵 전에 작은 조명 시험 구역을 만든다. 실내, 창가, 테라스, 물과 유리가 함께 보이는 수영장 시점을 포함한다. 낮·해질녘·밤·전환 중을 각각 측정한다.

같은 PC, 해상도, 카메라 경로, 품질, 오브젝트 수로 변경 전후를 비교한다. 로딩과 셰이더 준비 구간을 분리하고 준비 후 60초 경로를 3회 측정한다. 측정 시 VSync와 프레임 제한 상태를 기록한다. 에디터 수치만으로 최종 합격하지 않는다.

Development Player와 Unity Profiler로 병목을 분석하고, 최종 배포 빌드에서 체감과 프레임 시간을 재확인한다. 평균뿐 아니라 CPU/GPU 프레임 시간, p95/p99 프레임 시간, 메모리, GC 스파이크, 그림자·불투명·투명·후처리 패스 비용을 기록한다. GPU 타이밍을 얻지 못하면 측정 불가라고 명시한다. 임시 합격 기준은 시험 구간 p95 프레임 시간 16.67ms 이하이며 p99 및 반복 끊김은 별도 검토한다. FPS 제한만으로 합격 처리하지 않는다.

## 현재 설정 감사 — 2026-09-18

프로젝트 파일 및 설치된 URP 소스로 확인했다. 성능 측정은 아직 하지 않았다.

| 항목 | 현재 값 | 검토할 사항 |
|---|---|---|
| PC 파이프라인 | PC_RPAsset, 렌더러 모드 값 2 | 설치된 URP의 Forward+ 경로 유지 후 측정 |
| 주광원 그림자 | 활성, 2048, 거리 50m, 4 cascades | 작은 시험 구역에서 30m / 2 cascades 후보 비교 |
| Soft Shadows | High | Medium 후보와 근거리 그림자 비교 |
| 추가 광원 그림자 | 지원 활성, atlas 2048 | 지원 활성만으로 실제 사용량을 알 수 없음; 씬의 광원 수·종류 조사 필요 |
| SSAO | 활성, Downsample 꺼짐 | 절반 해상도 후보와 작은 소품 주변 품질 비교 |
| SRP Batcher | 활성 | 유지; CPU 제출 비용을 측정하고 draw call 감소와 혼동하지 않음 |
| Depth/Opaque Texture | 둘 다 활성 | 물·유리·후처리 의존성 확인 후 필요한 기능만 유지 |
| Render Scale | 1.0 | 1080p 원해상도를 기준으로 비교 |
| 실시간 반사 프로브 | PC 품질 설정에서 비활성 | 실제 반사 구성은 시험 씬에서 확인 |

위 후보는 아직 적용하지 않았다. 현재 설정은 변경 전 기준으로 보존한다. 한 항목씩 변경하고 동일 시점의 화면과 성능을 비교한 후 유지 여부를 결정한다.

## 조명 구성 방침

1. **태양·달**: 우선 하나의 실시간 주광원을 시간대에 따라 회전·색상·강도 변경한다. 태양과 달의 그림자를 동시에 계산하는 구성은 기본안에서 제외한다.
2. **실내 고정등**: 시간대 내내 유지할 빛은 베이크 후보로 분류한다. 움직이는 오리가 공간에 어울리도록 프로브를 시험한다. 모든 조명을 베이크하는 방식은 사용하지 않는다.
3. **밤에 켜지는 등**: 적은 수의 실시간 조명과 발광 재질을 조합한다. 발광 재질만으로 주변이 실시간으로 밝아진다고 가정하지 않는다. 조명이 벽을 통과해 보이면 범위·위치를 먼저 고치고 필요한 광원에만 그림자를 허용한다.
4. **추가 그림자 예산**: 첫 시험 구역은 주광원 그림자와 필요한 국소 그림자 최대 2개를 시작 예산으로 둔다. Point Light 그림자는 비용이 커질 수 있으므로 배치 목적을 검토한다. 이는 성능 보장이 아닌 초기 제한이다.
5. **낮밤과 간접광**: 실시간 태양 변화가 베이크 결과를 바꾸지 않는다. 낮 햇빛이 밤에 남는 구성을 피하고, 최초 시험에서는 실시간 직접광과 조절 가능한 환경광부터 검증한다. 실내 간접광·프로브·반사는 낮밤 모두 어울리는지 확인한 뒤 채택한다. 시간대별 베이크 교체·블렌딩은 별도 검증 없이 도입하지 않는다.
6. **반사**: 매 프레임 반사 프로브 갱신을 기본안으로 쓰지 않는다. 우선 고정 반사를 시험하고 밤에 낮 반사가 남는 문제가 있으면 시간대 전환 시 제한적인 갱신 또는 별도 반사 구성의 품질·스파이크·메모리를 비교한다.
7. **물·유리**: 투명 표면 겹침과 추가 카메라 렌더 비용부터 확인한다. 기존 물 셰이더가 요구하는 텍스처를 일괄 끄지 않는다.
8. **시인성**: 밤에도 길과 오리 단서는 읽혀야 한다. 그림자 축소, SSAO 축소로 가구가 떠 보이거나 빛 누수가 생기면 화면과 비용을 함께 보고 대안을 선택한다.

## 단계별 통과 조건

- 1단계: 작은 시험 씬에서 낮밤의 외관·시인성·빛 누수 확인.
- 2단계: 변경 전 동일 경로 실측 기록 확보.
- 3단계: 그림자, SSAO, 광원 수, 반사 갱신을 각각 비교하여 이득이 확인되는 설정 채택.
- 4단계: 밤과 전환 구간을 포함해 목표 PC에서 예산 검증 후 맵 확장.

## 매 작업 보고 양식

- **수정**: 어떤 파일·장면·문제를 어떻게 바꿨는지.
- **최적화**: 적용한 방법과 줄이려는 비용. 이미 켜져 있던 기능은 새 최적화로 집계하지 않는다.
- **검증**: 비교 조건, 변경 전후 수치, 화면 확인 결과. 실행하지 않은 검증은 명시한다.
- **남은 사항**: 화질 손실·미확인 항목·다음 측정. 이득이 없거나 문제가 생긴 변경은 복원 여부 기록.

### 2026-09-18 — 첫 조명 시험 맵 제작

- 수정: `VillaLightingStudy` 테스트 씬, 1인칭 검토 이동, 낮·해질녘·밤 조명과 6개 오리 위치 표식 제작. 야간 환경광·소품 겹침·책 방향 보정.
- 적용한 비용 제한: 주광원 1개 및 국소등 4개; 그림자는 주광원+Spot 2개만, 자동 시간대 갱신 10Hz, 단순 바닥 충돌체, 작은 장식 충돌 비활성, 매 프레임 반사 갱신 없음.
- 유지: 기존 PC 품질의 그림자 거리·분할·필터·SSAO. 빌드 중 Unity가 갱신하는 셰이더 필터 메타데이터는 수동 화질 변경과 구분한다.
- 검증: Unity 컴파일·씬 생성, 재질 누락 검사 0개, 낮밤 화면 캡처, 주요 경로 222개 지점 바닥 및 캡슐 여유 검사 통과.
- 성능: 첫 기준값 측정용 Development Player 빌드와 명시적 실행 인수 기반 벤치마크를 준비했다. 실제 측정 결과는 `MapBuild`에 따로 기록하며 이전 맵 대비 개선율은 주장하지 않는다.
- 상세 수정·최적화·제한: [첫 맵 작업 기록](MapBuild/README.md).
